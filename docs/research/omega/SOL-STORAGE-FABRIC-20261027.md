## What actually runs

- `.github/continuum/storage-fabric.mjs`: independently authored Node stdlib AES-256-GCM block envelope, SHA256 ciphertext and plaintext validation, strict file helpers, authenticated local block adapter and non-executable storageManifest export. Existing Virtual Model Fabric remains unchanged. The parent may consume this narrow descriptive export; it grants no access or compute authority.
- `scripts/continuum-storage-fabric-node.mjs`: two explicitly configured owner-private directories, each served by its own real localhost subprocess. Scoped bearer tokens authorize read/write/delete/status for one namespace. Exact paths, 64hex hashes, request/body/connection/deadline/file/quota limits and no-follow filesystem checks reject traversal and symlinks. Encrypted blocks are written with temp-file fsync, rename and directory fsync.
- `.github/continuum/storage-fabric-catalog.mjs`: single-writer central catalog, bounded immutable HMAC-authenticated versioned snapshots, object versions and durable tombstones. All configured replicas must accept a write before object metadata commits. Read validates every returned ciphertext and AEAD/plaintext hash, fails over and can use an integrity-checked encrypted bounded cache. Explicit repair re-uploads and re-reads replicas. Delete durably tombstones all versions first, records pending physical deletion and reconciles after a node returns.
- `.github/continuum/storage-fabric.test.mjs`: real process/network/filesystem tests using synthetic deterministic payloads only. Secret tokens/key are transient in memory/private0600 configs outside Git; subprocesses and temporary state are stopped/removed on completion. Malicious-looking bytes are stored as inert data; tests do not execute candidate host code.

Root paths must be existing absolute directories with owner-only permissions. Configs are absolute private0600 JSON outside the repository, with nodeId, namespace, root, quotaBytes, port and tokens[{token,namespace,operations}]. Tokens require32+characters. CLI: `node scripts/continuum-storage-fabric-node.mjs /absolute/private/config.json`. Binding is127.0.0.1 only; remote deployment would require separately authorized TLS and network controls. No permanent service was left running.

GET/PUT/DELETE `/v1/<namespace>/blocks/<ciphertext-sha256>` and GET `/v1/<namespace>/capacity` form the reference adapter seam. ReplicatedStorageFabric.open({catalogRoot,cacheRoot,encryptionKey,nodes}) exposes put/get/delete/repair/reconcileDeletes/manifest/close. Objects are capped at1MiB, blocks64KiB,2–4replicas,64objects/8versions/128catalog revisions; servers at64MiB quota. This is intentionally bounded research rather than a500GB implementation.

Catalog is central and NOT highly available. No quorum, distributed lock, network partition consistency, cross-region fault tolerance, FUSE, Android/Termux run, SEAWEED backend, model weight transfer, inference, disk-full fault injection or500GB/TB benchmark was run. Random per-block encryption avoids nonce reuse but does not implement cross-object plaintext deduplication. Failed writes may leave encrypted orphan blocks within server quotas; no automatic GC is claimed. Bounded fsync+rename is host filesystem durability, not proven power-loss recovery. Graceful restart was tested; abrupt crash may leave fail-closed lock or temporary files requiring owner inspection. HMAC rejects catalog changes but cannot independently detect deletion of the latest signed suffix without an external monotonic anchor. Local owner-concurrent path replacement is outside the localhost research threat model; this is not an OS sandbox. Old tombstoned versions cannot be reopened; deleting an object is a logical tombstone plus best-effort durable pending physical deletion, not a claim of cryptographic erasure. Capacity measurements do not reserve bytes against other writers on the filesystem.
