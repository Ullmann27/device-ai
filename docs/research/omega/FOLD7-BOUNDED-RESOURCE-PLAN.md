# Fold7 bounded resource plan — design caps, not measured device capacity

No device is connected here. Physical RAM, current PSS, native allocation, thermal state and battery are UNKNOWN. Flash, mmap address space, quantized file size, swap and VirtualModelFabric experts are never added to available RAM.

1. Read Android ActivityManager.MemoryInfo(totalMem,availMem,lowMemory,threshold), Runtime.maxMemory/freeMemory, Debug.getPss/native heap and existing battery/thermal guards before load and per bounded job. Stop if measurements are unavailable or lowMemory/thermal/battery veto is active; retain current checkpoints.
2. Initial proposed scratch cap = min(128MiB,available physical memory/8,Java heap headroom/4). This is a conservative candidate limit to validate on the actual Fold7, not a claim that128MiB is free. Reserve at least max(system low-memory threshold,20%physical RAM) from observed availMem. PSS/model headroom must fit independently; no allocation merely because a capability manifest advertises RAM.
3. Keep model files on private flash with hashes/revisions; read-only mmap/lazy pages only where the existing runtime supports it. Count resident mmap pages in PSS. Keep one large Gemma runtime resident at a time; release through its existing lifecycle before loading another large model. Do not implement a second loader or pretend mmap removes physical working-set cost.
4. Quantization is a separate measured candidate: compare factual/abstention quality, P50/P95, peak PSS/native heap and load time against the currently supported runtime. Preserve original file and rollback identity; no automatic conversion/promotion.
5. Lazy-load the32932-byte research asset only on explicit lab entry. Bound snapshot≤4sources/4096chars, ranker≤1024UTF8bytes. An optional LRU cache must be byte-capped by the observed scratch budget, keyed by source+revision+hash+model+session, and evict on revision/model/session change. No cache entry extends validity or owner authority.
6. At TRIM_MEMORY_RUNNING_LOW/CRITICAL, OOM, cancellation or thermal veto: cancel research, evict disposable caches, close mapped research resources, preserve owner data/checkpoints and return controlled abstention. Never retry an OOM in an unbounded loop. Existing Android background/battery/thermal scheduling remains authoritative.
7. Offload only through existing ComputeFabric/VirtualModelFabric signed-capability/result interfaces after actual authorized transport exists. Scheduler checks task RAM/runtime/output caps and revocation. Local physical limits stay unchanged when a remote node is available; no device data upload without existing owner/data gates.

Acceptance before changing defaults: real Fold7 baseline and candidate peak PSS/native/Java, available-memory trace, model load and answer P50/P95, battery/thermal/background run plus forced cancellation/low-memory negative tests. Current host-only measurements are saved separately and cannot establish this device gate. No new memory manager, database, swap promise or permission was implemented.
