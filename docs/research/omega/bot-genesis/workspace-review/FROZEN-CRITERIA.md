# GENESIS workspace/handoff independent criteria v1

Frozen before any Genesis adapter implementation inspection. Baseline:
`4b881f81ddfbe38729a551d9e460e818c6b3b715`. Remote MΩ read-only entrance:
`5feb1a93ffe5db29163e33e4a0ea002ff25252fe`, fetched during this audit.
Role: independent reviewer. No production edits, model inference, heavy build,
owner-data access or claimed Android sandbox acceptance.

Acceptance cases:
1. Resolve stable from/to agent IDs through existing persistent profiles; unknown
   IDs and display-name impersonation reject. Rename changes neither association
   nor authority. Registered profile alone cannot run tools or certify competence.
2. Distinguish persistent `workspace-bot-X` from per-run `continuum-<hash>` sandbox.
   Bind both through the trusted actual executor observation; no naked string
   supplied by a model becomes a profile, grant, receipt or security boundary.
3. Bind task, job, current source, attempt, request message/hash and grant fingerprint
   on every handoff. Mismatched, expired and late replies cannot advance the task.
4. Current canonical CCC1 grant, lease, deadline, revocation and source checks apply
   immediately before effectful work and after result return; historical consent
   and a bot message are not new owner approval.
5. Builder and verifier principals must differ, even when one registered specialist
   declares both capabilities. An arbitrary `DONE` report or own success prose
   remains unverified; evidence references are resolved by the canonical verifier.
6. One original task budget: stage/child reservations debit remaining model/tool/
   wall/output/message budget. No new full budget per bot, per retry or per restart.
   Conservation and exactly-once charges must survive simultaneous admission.
7. Existing mailbox bounds remain global. Typed metadata references canonical task
   evidence, not a second task journal. Expiry is checked on consumption as well as
   send; full mailbox and rejected delivery are visible, not silently successful.
8. Duplicate message delivery cannot rerun the stage. Cancellation, timeout or
   unknown termination cannot be undone by late callback or automatic replay.
   Persistence/restart authority stays in canonical CCC1/backlog, not mailbox RAM.
9. Mnemos stores only canonical independently verified technical experience using
   existing recordTechnicalExperience. Current-grant recall, lineage and revocation
   remain authoritative; full-ledger withdrawal and tampered mirror tests stay on.
10. Echo may summarize verified, rejected, uncertain and blocked evidence separately;
    it cannot relabel historical success as current-code correctness or local/model
    proof. Host fixtures remain HOST_INTEGRATION, never FOLD7_VERIFIED.

Initial typed flow uses one authorized coding task: Atlas proposes a bounded stage,
Forge produces candidate, Lint independently verifies via existing fresh-worktree
path, Mnemos invokes existing admission, Echo renders the resulting receipt status.
This is five identities with three execution classes (planning/build, verification,
post-result handling), not five models or five independent OS instances. Do not
simulate stages that have no executable caller. Physical local-model success is a
separate MΩ gate, not provided by this contract.

Stop on identity leak, rights expansion, budget inflation, duplicate effects,
unconfirmed teardown or revoked recall. Preserve rejection evidence. Adding the
adapter does not waive existing RED/GREEN, ToolGate or independent verification.
