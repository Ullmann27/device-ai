## Canonical worker, leases and recovery

Do not add parallel worker/receipt/backlog systems; these already exist and are connected in Node:

* `.github/continuum/shared-build-lease.mjs:52` creates an exclusive atomic lease keyed by real source root; `:27` is an explicit dead-holder release requiring same host and provably dead PID. Age alone does not free it. `.github/continuum/autonomous-teamleader.mjs:171` acquires this lease.
* `.github/continuum/development-backlog.mjs:413,488,496` binds claim/renew/submit to per-attempt tokens; `:531` expires leases; `:630` starts file locking, backup and atomic-store recovery. `.github/continuum/backlog-repair-worker.mjs:101` recovers expired claims then claims the canonical task.
* `.github/continuum/ccc1-journal.mjs` validates sender/role, chain and MAC and rejects corrupt/torn journals. `.github/continuum/ccc1-recovery.mjs:54` repairs a torn last tail, verifies entries, reconciles source/worktrees, and classifies pending request deterministically. `:80–83` sends interrupted claimed work to REQUIRE_OWNER_APPROVAL, finished unrecorded work to receipt replay, and only never-started work to execute. No silent success/re-execution.
* `.github/continuum/local-teamleader-loop.mjs:227–235` consumes an interrupted RUNNING cycle as INTERRUPTED/failure, persists remaining budget/backoff; durable lock recovery is at `:97–140`. Tests include actual SIGKILL/restart and competing schedulers. This is implemented worker lifecycle logic, not proof that a phone worker is currently running.
* Android uses the same backlog format/FSM through `cognitive/DeviceDevelopmentBacklog.kt:75` (`startJob` propose/accept/claim), `:89` (`finishJob` proposal submit/fail), `:109` (lease recovery), lease 300,000 ms (`:170`). `cognitive/DeviceTeamleader.kt:134` supervises integrity/recovery only and explicitly states READY does not prove Git/Gradle worker success (`:45`). Android/Termux have separate filesystem storage; canonical format compatibility is not continuous automatic state synchronization.

No live owner-phone worker, lease file, installed model, APK or signing identity was queried. Do not report a current phone heartbeat from source existence or fixture tests.

## Concrete defect to repair first

`AgentActivity.startDevelopmentJob`, lines 6069–6081: `devBacklog.startJob(task)` is wrapped in `runCatching`, but `coordinator.run(task)` runs unconditionally when the claim/save failed. `finishJob` is then skipped by `backlogToken.mapCatching`; only a later toast reports failure (`:6089`). Thus inference can start without the durable IN_PROGRESS record/claim/lease whose crash-recovery guarantee the adjacent comment asserts. A corrupt/unwritable/locked backlog can produce untracked model work.

Exact next implementation step: return a fail-closed UI outcome on failed `startJob` **before** `coordinator.run`; add a focused meaningful regression with an injected failing job-claim recorder and model-call counter proving zero model calls, cleared busy state and preserved backlog evidence. Product source was not modified by this audit.

After that, the smallest actual Android continuity milestone is a reviewed task-draft handoff from chat/development proposal into the existing typed form, with commit/path/acceptance completion and owner review still explicit. To claim Android coding execution, implement and prove a mobile confinement backend before relaxing the existing CODING_ISOLATION_UNAVAILABLE gate; do not substitute unrestricted Termux shell or label Docker as on-device.
