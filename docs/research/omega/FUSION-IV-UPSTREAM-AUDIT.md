## Source defects and compatibility limits

- TokenArc `AgentCore.kt:32` constructs `ScreenReader(context)`, while `ScreenReader.kt:6` requires `JarvisAccessibilityService`. This is a source type mismatch, not a successful upstream Android build. `AgentCore.kt:38` creates a plain `CoroutineScope(Dispatchers.IO)`; the reviewed file exposes no lifecycle cancellation of that scope.
- TokenArc `ScreenReader.kt:44–68` and `:78–100` use unbounded BFS; extraction at `:16–35` is unbounded recursion/output. BFS recycles the root before the caller recycles it again on a miss; a root match can be returned after the caller recycled it. Early returns leave queued nodes unreleased. The service's own `findNodeByText` repeats the unbounded/ownership pattern. These are static ownership/resource defects, not device crash reproductions.
- TokenArc `ActionExecutor.kt:40–49` reports a package launch successful after a void method that silently does nothing when no launch intent exists. Back/home/recents at `:75–87` ignore `performGlobalAction`'s Boolean. Dispatch also supplies no independently observed postcondition. Continuum's preexisting `DeviceToolExecutor.kt` similarly emitted a launch message after a Shizuku command; a foreground-verification adapter is still real engineering work.
- OpenJarvis `check_call` keys warn-before-block by the full `reason`. `_python_check` embeds the increasing identical-call count in that reason, so the default Python path can issue a new warning on every repeated identical call instead of blocking it. That early return also skips poll/pattern checks. **STATIC FINDING / NOT_RUNTIME_TESTED**. The per-tool budget is applied to every tool, although the docstring describes polling metadata. `LoopGuardConfig.enabled` is not consulted in the reviewed check path. Do not inherit these semantics.
- TokenArc declares minSdk 26, compile/target 34, Java/Kotlin target 17; Continuum uses minSdk 26, compile/target 36, JVM 17. This supports examining the Android API shapes, not dropping in the application. Its Compose/Room/KSP/coroutines/ML Kit stack and permission manifest are not needed for bounded native launch/reading. Android 36 service behavior, lifecycle, visibility and device behavior require Continuum tests.
- OpenJarvis is a Python 3.10–3.13 backend with an optional Rust bridge, not a native Kotlin Android component. Dix01 combines Python services, web UI and Electron; its wake helper is portable as an algorithm, not as a packaged Android voice engine.
- Existing Continuum speech recognition uses an external recognition activity with `EXTRA_PREFER_OFFLINE=true`; that is a preference, not proof that no audio leaves the device. None of the reviewed text helpers proves offline STT/TTS, local model weights or microphone/camera lifecycle correctness.
