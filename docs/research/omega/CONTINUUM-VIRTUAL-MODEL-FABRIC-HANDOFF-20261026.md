## Decision / what is newly useful
Keep the small, owner-controlled Continuum brain, its on-device memories and canonical Android Coding/CCC1 chain. Add a **virtual model identity / planning layer**, not another Coding Agent. A logical address can resolve to a local already-installed small model or an authorized, operator-hosted larger model at a pinned revision, under explicit privacy, consent, cost and time budgets. It need not assume the full ~500GB weights are present on the phone. A stable address is **not proof of permanently available processing capacity**; the new module returns a proposed route, never an executable privilege.

The nonobvious high-value research hypothesis: save **independently verified repair recipes + exact preconditions/counterexamples** and test whether local model + safe retrieval reduces authorized calls to a rare remote large teacher at equal independent Pass@1. This is a falsifiable *reduction in remote calls per verified novel repair*, not a claim to compress 510GB to almost zero.

## Research options / prioritization
A. Pinned endpoint that is already hosted and explicitly owner-approved, including true no-charge constraints. **Best immediate path** if an operator endpoint actually exists.
B. Persistent object storage + time-rented compute and weight cache. Compute remains physically required; no cost incurred without owner approval.
C. Cooperative / distributed inferencing with consenting worker nodes (possibly Petals-style research). Network throughput, privacy, failure recovery and model-family compatibility require real measurements.
D. CPU/SSD expert offloading where official model and runtime support it; new engineering only after actual counters.
E. Local recipe replay + model router to minimize heavyweight calls. Test first: highest potential verified benefit with low hardware and no bills.
Never claim 'OneToken', virtual GPU or '500GB vanishes' without a precise verified implementation and an empirically measured bound.
