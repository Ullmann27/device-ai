## Method

Isolated Linux **host**; OpenJDK `21.0.12.1`, Kotlin JVM `1.9.0`, 8 visible CPUs. The original complete tokenizer source was copied byte-for-byte (Git blob verified), then compiled with its package renamed to `.original`; each candidate differed only at one method and was compiled as `.candidate`. The source-derived deterministic vocabulary fixture was *not* trained into any owner model; the exact same serialized fixture feeds both packages. Separate A/A before edit and A/B after edit for each target; fixed 8 scenarios, 4 alternating warmup pairs and 9 alternating measurement pairs. A process aborts if the initial host load exceeds visible CPU count. Measurements were made once per phase without a favorable-value rerun. Time, thread CPU and thread allocated bytes were captured via the JDK management bean. Numbers below are the **medians of whole 120-input batches**, not per-call values. Host-to-host variation and control regressions prevent general performance claims.

### R4 — encodeWord primitive in-place compaction

The candidate replaced boxed mutable `Int` lists and intermediate lists for each merge with an `IntArray`, preserving ranked merges and cache keys. Token/UTF-8/serialization parity passed **2,544** cases; all 8 A/A and 8 A/B matrices completed. Allocation decreased by 16.0% on cold byte-ASCII, 18.4% on cold byte-Unicode, 20.9% on cold learned ASCII and Unicode, and 14.9% on cold learned-long. However, CPU median **increased** 64.8% for cold learned-long (0/9 favorable pairs), 58.4% for the learned cache-hit control (0/9), and 112.1% on byte-punctuation control (0/9), despite some strong gains elsewhere. Since these adverse controls are not explained, this is **REJECTED**; no retiming or general adoption.

### R5 — decode exact-byte preallocation

The candidate pre-counted output bytes and performed one copy into an exactly-sized array instead of using `ByteArrayOutputStream`. Decode/token/checkpoint identity parity passed **3,960** cases; all matrices completed. Allocations decreased on all eight scenarios (32.5%–53.9%), but CPU increased **77.4%** on the tiny-byte control (0/9 favorable pairs), **141.4%** on the single-word control (0/9), and 19.6% on mostly-ignored ID controls (1/9). **REJECTED**; no general `decode` replacement.

### R6 — direct regex match-list collector

The candidate removed the chained sequence `map { ... }.toList()`, explicitly preserving the same 0/1/many list behavior. Boundary and downstream encoder/token/checkpoint parity passed **3,960** cases; all matrices completed. There was **no measured reduction in allocated bytes in any of eight scenarios**. CPU results were mixed; whitespace control increased 14.4% with only 2/9 favorable pairs. **REJECTED**.
