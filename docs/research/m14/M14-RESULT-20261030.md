# M14 · Wiederanlauf und Arbeitssteuerung – echte Absturztests des bestehenden Teamleaders

**Neu:** `.github/continuum/teamleader-chaos.test.mjs`. Jeder Worker läuft als **eigener Node-Prozess** mit dem echten `runTeamleaderCycle`. Abstürze werden als echte `SIGKILL` ausgelöst, nicht durch Bearbeiten der Zustandsdatei simuliert. Es gibt keinen neuen Scheduler und keinen neuen Worker.

| Szenario | beobachtetes Verhalten | Bewertung |
|---|---|---|
| `SIGKILL` mitten in der Reparatur, Neustart sofort | **verweigert** („lock requires recovery“), keine zweite Reparatur | fail-closed, gewollt: Sperren toter Prozesse gelten 5 Minuten lang (PID-Namensräume Termux/Container) |
| Neustart nach > 5 Minuten | Teamleader-Sperre übernommen, **danach blockiert die Build-Lease** (`CONTINUUM_BUILD_LEASE_BUSY`) | **Lücke:** Die Lease wird nie nach Alter freigegeben (gewollt). Die vorgesehene Besitzer-Freigabe `releaseDeadContinuumBuildLease` hatte aber **keinen Befehl**, nur Tests riefen sie auf. |
| **neu:** `teamleader-cli.mjs --release-dead-lease` | gibt die Lease nur frei, wenn sie diesen Host und einen nachweislich toten Prozess nennt; sonst Verweigerung mit Grund | Besitzerschritt, kein Automatismus |
| danach Neustart | läuft, Ereignis **INTERRUPTED** protokolliert, Zustand integritätsgeprüft, **keine Wiederholung** der Reparatur auf demselben HEAD | erfüllt |
| zwei Worker gleichzeitig | genau einer repariert, der andere wird verweigert | erfüllt |
| abgeschnittene Zustandsdatei (Stromausfall beim Schreiben) | verweigert, Datei bleibt als Beleg unverändert, keine Reparatur | erfüllt (fail-closed) |
| fehlender `PATH` (kein git, keine Werkzeuge) | Kernzyklus läuft, Zustand gültig | erfüllt (der echte Treiber mit git wurde hier nicht getestet) |

Tests: Chaos 4/4, Teamleader 31/31 (neu: CLI-Modus), Lease 12/12, zusammen 47/47.
