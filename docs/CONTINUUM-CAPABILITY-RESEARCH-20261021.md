## Protocol declared before measurement

All algorithms are reporting-only new modules. No production imports them; importing them performs no writes, network requests, training, tool execution, or checkpoint promotion. They reuse the existing `SubwordEncoder` snapshot format, `rankMemories`, and restricted `isLocalNumericPatch` candidate interface. The ANSK contract, replay critic, NEURON state/export interfaces and CDX1 conditioning interface were inspected. Numeric laboratory receipts do not masquerade as ANSK Android compilation receipts. A single canonical repair/backlog pipeline remains the future integration point.

1. **Counterexample-guided finite synthesis.** Generate a fixed typed integer-expression grammar without task labels. Starting from two examples, compare passive, seed-shuffled input acquisition with maximal-disagreement input acquisition and counterexample elimination. Both receive at most eight additional oracle answers. An exhaustive evaluator scores the chosen expression on a larger integer domain, with expected outputs authored independently from the AST interpreter. Report exact task success, residual error count, oracle calls, candidate evaluations and remaining version-space size, including out-of-grammar cases. An oracle is available only because these are authored tasks; this is a finite laboratory, not a proof over arbitrary numbers or code.
2. **Content-addressed, revocable repair memory.** Learn only operator-replacement hints whose original repair passes actual in-memory integer tests. Bind the source task snapshot, original/repaired AST, executed input/output evidence and split membership to a content hash. Verify provenance against an external, caller-owned training registry; hashes are corruption checks, not authentication. Replay hints as candidate order only, then independently execute the same target verifier used by a no-memory enumerator. Compare verified candidate attempts and execution cost. Include naive unverified replay as an explicitly unsafe negative control. Rehashing forged evidence, cross-split import, corrupted bytes, negative transfer and revocation must not create an accepted hint. A revoked hint cannot be reused even if a previously returned receipt remains present.
3. **Uncertainty-aware context selection.** Use the existing lexical retriever and a restored, frozen SWB1 snapshot as a committee. Confident agreement may use one compact evidence item; disagreement uses budgeted maximal-marginal-relevance selection with duplicate and repair-strategy diversity penalties. Compare with actual lexical prefix packing and frozen SWB1 prefix packing. All methods have the same conservative UTF-8-byte/4 cost proxy and budget; it is explicitly not a tokenizer measurement. Report relevant-hint coverage, irrelevant admissions, context cost, committee agreement, and subsequent verified repair attempts. Neither committee agreement nor a neural score verifies a repair.

Training seeds are `[11, 29, 47]`; holdout seeds are `[101, 211, 307]`. Training families are elementary sum, signed difference, lower envelope and upper envelope. Holdout families are absolute distance, positive gap, interval saturation and two-sided gap; adversarial families include product outside the synthesis grammar, operator reversal, source/proof tampering, train/holdout aliasing and revoked context. Family names, task IDs and snapshot hashes are checked for overlap before fitting. Public authored holdouts are consumed once for this report; future tuning requires new families and seeds.

Budgets are fixed: synthesis atoms `x,y,-2,-1,0,1,2`, operators `add,sub,min,max,abs`, maximum expression size five nodes, eight acquisitions; query domain `[-4,4]^2`, score domain `[-9,9]^2`; repair mutation operators `add,sub,min,max` and maximum 32 attempts; context budget 120 byte-cost units, lexical agreement margin 0.08, SWB1 margin 0.04, MMR diversity penalty 0.45. No threshold, grammar, gate, family assignment or budget may be changed to turn a measured regression into a positive result. Algorithm-correctness fixes must be disclosed separately from outcome-driven tuning.

## Results

The fixed audit ran under Node v24.19.0, Linux x64. The targeted executable suite passed 14/14 tests. The runner executes each complete audit twice in its determinism test, compares the entire canonical report, and includes all task rows, generated counterexamples, verified candidate traces and source/model/data hashes. There was no policy, task, grammar, split or budget tuning after outcome inspection. Two unit fixtures were corrected: the overflow probe originally computed a still-safe integer, and the intended lexical tie probe originally contained unequal text. Neither correction changes the experiment fixtures or policies.

Grammar generation cost is shared by both synthesis arms: 3,203 generated terms, 688 distinct query-domain behaviors and 259,443 interpreter evaluations. Memory admission additionally costs **12,996** proof-input executions for twelve training receipts, before any target task runs. These costs rule out a demonstrated total-speed improvement on this small run. The SWB1-only retrieval baseline covers 9/12 relevant hints and needs eighteen repair attempts; the snapshot has zero training updates. The committee uses its uncertainty/diversity route on every holdout: **zero compact agreement routes**. Consequently this audit does not establish that neural scoring or uncertainty gating improves over lexical retrieval; diversity and byte packing account for the observed context behavior, and there is no component ablation supporting a stronger attribution.

The twelve rows comprise four declared syntactic task families over three disjoint seeds, but only **five distinct source/oracle pairs and four distinct bounded-domain oracle functions**. Absolute distance and two-sided gap have identical expected outputs. Seeds vary passive query acquisition and query identifiers, with two interval bounds; they are not twelve independent competencies. Training and heldout families/seeds/IDs and source/evidence aliases are checked before fitting. Because these are public authored tasks, the holdout is now consumed and cannot justify subsequent tuning or promotion.

Six attacks (corrupt bytes, self-rehashed false proof, holdout provenance, family alias, source drift and forged training permission) were all rejected. Renamed train/holdout content aliases were rejected. Revocation blocks saved-receipt reimport and stale context IDs; fallback remains subject to target verification. Outside-grammar multiplication yields abstention. An explicitly unsafe nearest-hint replay makes **two false success claims** on the three adversarial tasks; the verified arms accept **zero wrong repairs on the tested finite domains**. A misleading negative-transfer hint is executed and rejected, then the fallback repairs it. No memory-attempt regression occurred in this fixed task set; the wrong-hint checks are nevertheless real. No broad Node suite, Gradle, Android build, Samsung runtime, independent Git worktree, model training, checkpoint write or production repair was run for this laboratory.

## Compatibility, limits and rollback

All new structures are laboratory version 1 and advisory. No Kotlin/Android components, weights, existing fixtures, production recipes, owner facts, CDX1 bindings or live models are changed. The restricted JS adapter passes candidates through the existing numeric syntax validator; it grants no execution permission. The in-memory arithmetic interpreter does not evaluate generated strings or execute model text. Fresh canonical critic, test-chain and independent-worktree checks would still be required before any real repair use. Android on-device availability, CPU/memory/thermal cost, CDX1 generation quality and general language competence remain unmeasured.

Next experiment: seal a separately authored external task family and collect prospective Android/Termux operation and memory measurements, using the canonical repair worker only after explicit integration review. Rollback: remove the new `capability-research*.mjs` modules and this document; no data or model migration exists.
